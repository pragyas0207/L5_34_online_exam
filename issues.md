# Static Analysis Issues

Static code analysis helps find security risks, bugs, and maintainability problems before they cause trouble at runtime. The following issues are based on the baseline Pylint, Flake8, and Bandit reports and direct review of `online_exam.py`.

| Issue | Type | Line(s) | Description | Fix Approach |
| ----- | ---- | ------- | ----------- | ------------ |
| Shell command uses untrusted input | Security — High (Bandit B605; High confidence) | 54–56 | `lockScreen` builds a shell command by concatenating `labPc`. If that value contains shell syntax, it can change what command runs. The helper is not called by the demo, but remains callable. | Avoid shell interpretation; invoke SSH with `subprocess.run` using an argument list and validate the host value. |
| Weak MD5 hash | Security — High (Bandit B324; High confidence) | 15–16 | Bandit flags MD5 as a weak hash. Here it is used to compare known answer strings, rather than to protect stored credentials, but it can give a false sense of cryptographic security and is unnecessary for direct normalized string comparison. | Compare normalized answers directly, or use a modern hash only if a security requirement calls for hashing. |
| Mutable default argument retains penalties | Bug / Code quality — Medium (Pylint W0102) | 23, 30 | The default `{}` is created once and reused across calls. Penalties can therefore carry over between separate `gradeStudent` calls when no dictionary is passed. | Use `None` as the default and create a fresh dictionary inside the function, or require the caller to pass the mapping. |
| Missing guard for empty topper results | Bug / Edge case | 51–52 | `max()` raises `ValueError` when `results` is empty. The demo populates results first, but calling `topper()` before grading any student fails. | Handle the empty case explicitly, such as returning `None` or a clear message. |
| Hard-coded password-like value | Security — Low (Bandit B105; Medium confidence) | 11 | Bandit identifies `"proctor-demo"` as a possible hard-coded password. The constant is currently unused, but keeping a real credential in source would expose it to anyone with repository access. | Remove it if unused; if authentication is added, load secrets from an appropriate external configuration or secret store. |
| Non-cryptographic random choice | Security — Low (Bandit B311; High confidence) | 19–20 | Bandit notes that `random.choice` is not intended for security-sensitive randomness. This is only a concern if the bonus question must be unpredictable to deter exam gaming; it is not a cryptographic operation in the current demo. | If unpredictability is a security requirement, select with `secrets`; otherwise document that this is a casual random demo choice. |
| Naming, documentation, and iteration style | Code quality / Maintainability (Pylint C0114, C0116, C0103, C0200, R1705) | 1, 15, 19, 23, 25, 35, 37–42, 45, 51, 54, 59 | Pylint reports a missing module docstring, missing function docstrings, camelCase function/argument names, a `range(len(...))` loop, and an unnecessary `elif` after `return`. These make the code less consistent with Python conventions and harder to understand and maintain. | Add concise docstrings, use snake_case, iterate with `enumerate` where appropriate, and simplify the conditional. |
| Formatting violations | Style (Flake8 E302, E225, E261, E501) | 54, 67, 69–70 | Flake8 reports insufficient blank lines before `lockScreen`, missing spaces around the assignment operator, insufficient spacing before an inline comment, and a line exceeding 79 characters. These reduce consistency and readability. | Apply standard Python formatting: add the blank line, spaces, comment spacing, and wrap the long output statement. |
| Importing the module runs the demo | Maintainability | 73 | The unconditional `main()` call means importing `online_exam` immediately prints output and mutates global `results`. This makes the functions harder to reuse and test independently. | Call `main()` only under an `if __name__ == "__main__":` guard. |
